## Executive Summary

Successfully identified and fixed the **ROOT CAUSE** of CD pipeline failures. The issue was in the shared workflow's version code calculation logic, which affected all Android projects using this workflow.

## ✅ FINAL FIX: Version Code Calculation (PERMANENT SOLUTION)

### 🐛 **Root Cause Identified**
The shared workflow (`.github-workflows-shared/.github/workflows/android-cd.yml`) was calculating Android version code incorrectly:
```bash
# OLD (BROKEN) - Line 97
CODE=$(git rev-list --count HEAD)
```

This counts **total commits in the repository**, which:
- Always returns the same number (184 for TelePort)
- Never increments with new releases
- Causes "Version code X has already been used" errors in Google Play Store

### ✅ **Permanent Fix Applied**
Changed version code calculation to derive from the semantic version tag:
```yaml
# NEW (FIXED) - Lines 97-116
- name: Calculate Android Version Code
  id: android-version
  run: |
    # Get the new tag from version bump step
    NEW_TAG="${{ steps.version.outputs.new-tag }}"

    # Remove 'v' prefix
    VERSION="${NEW_TAG#v}"

    # Split into major, minor, patch
    IFS='.' read -r MAJOR MINOR PATCH <<< "$VERSION"

    # Calculate version code: MAJOR * 1000000 + MINOR * 1000 + PATCH
    CODE=$((MAJOR * 1000000 + MINOR * 1000 + PATCH))

    echo "Version: $VERSION -> Version Code: $CODE"
    echo "code=$CODE" >> $GITHUB_OUTPUT
  shell: bash
```

### 📊 **How It Works**
- `v1.5.14` → version code = `1,005,014`
- `v1.5.15` → version code = `1,005,015`
- `v1.5.18` → version code = `1,005,018`
- Version code **ALWAYS increments** with each new release
- **NEVER conflicts** with Google Play Store

## Prevention Strategies

### 1. **Version Code Management** ⚠️ **CRITICAL**
- **Never delete tags that have already been deployed to Play Store**
  - Once a version code is uploaded to Google Play Console, it's permanently registered
  - Deleting the git tag doesn't remove it from Play Store
  - This causes version code conflicts when CD recalculates

- **If you must clean up tags**:
  1. Check Play Console to see which version codes are uploaded
  2. Only delete tags that were never deployed
  3. Immediately trigger a new CD run to create the next version
  4. The new version will skip the conflicting version code

- **Best Practice**: Let CD manage all tags and never manually delete them

### 2. **Tag Management**
- Never manually create/push tags that CD will create
- Let CD workflow handle all version tagging automatically
- If tags need to be deleted, do it immediately before triggering CD

### 3. **PR Merge Discipline**
- Review and merge PRs within 24 hours of CI passing
- Use squash merge to maintain clean commit history
- Check for conflicts before merging multiple PRs

### 4. **Monitoring**
- Monitor CD runs via: `gh run list --workflow="cd.yml" --limit 5`
- Check runner status: `gh api repos/ravitejakamalapuram/TelePort/actions/runners`
- Review failed runs immediately: `gh run view <id> --log-failed`
- **Check for version code conflicts**: Look for `Version code X has already been used` errors

### 5. **Runner Maintenance**
- Keep `scripts/fix-runner.sh` handy for quick restarts
- Regular runner health checks (weekly)
- Monitor runner logs: `tail -f ~/github-runners/TelePort/Runner1/_diag/Runner_*.log`
